## 用户执行

先开启USB接收：

```sh
sudo SWEET_ACM_DEVICE=/dev/ttyACM0 /home/shenli/work1/ref/ios-mh2lm/tools/sweet-usbacm-log.sh /home/shenli/work1/logs/live-0121a34-abi608-panel-pipeline.txt > /dev/null 2> /home/shenli/work1/logs/live-0121a34-abi608-panel-pipeline-host.txt
```

该终端静默是预期，采集脚本独立写日志文件。要看到输出，另开终端读取文件：

```sh
tail -n 40 -F /home/shenli/work1/logs/live-0121a34-abi608-panel-pipeline.txt
```

再在另一终端临时启动：

```sh
fastboot boot /home/shenli/work1/out-bs/boot-16k-0121a34-abi608-panel-pipeline.img
```

1. 先确认桌面、触摸和持续更新正常；应有启动`command buffer ready bytes=4096`、首次generation1及`SWEET FB HANDOFF: active`。如果首次接管异常，先保存日志，不继续OFF测试。
2. 息屏约5秒，按电源键唤醒；正常恢复后保持接收至少60秒，查看画面、触摸/按键和持续呈现。再做第二轮同样的OFF/ON。若某轮失败，保存现场并记录操作时刻，不重复同条件循环。
3. 保存USB及host文件，按既有流程提取持久日志到`logs/sweetlog-0121a34-abi608-panel-pipeline.bin`。再次测试用新后缀，避免混入/覆盖本轮记录。

OFF本轮重点顺序：

```text
HS branches halted; PLL/bias stop issued; checking ULPS lane idle
ULPS entry lane-status=... mask=0x1f want=0
ULPS entered after HS stop; PHY shutdown next
OFF complete
```

第一条只证明分支已halt和PLL/bias停止请求已发出，不能当作PLL unlock完成证明。若停在新lane-idle检查，保留USB及持久日志，不能放宽检查绕过。

ON应沿原流程完成供电/ULPS重入退出、host和panel reset、17条ON命令及四条物理DMA、display引擎引用1、generation2/3、新像素、触摸和ON complete。启动之后不应再分配命令缓冲。`FB owned resume verified`受既有诊断次数限制，第二轮缺这一行不能单独判断失败，需要合看generation/ON complete/后续帧与输入。

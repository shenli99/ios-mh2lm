```sh

```

需要看实时输出可另开终端执行 `tail -n 40 -F /home/shenli/work1/logs/live-0121a38-abi608-panel-pipeline.txt`。

1. 检查首次桌面、触摸、按键及低/中/高调光，观察同一画面的颜色、亮度和持续刷新。首次亮度/音量滑条差异分别按 BUG-008/009 记录。
2. 息屏约5秒再唤醒，共两轮；**每轮唤醒正常后保持亮屏至少60秒**。观察亮度/色彩是否保持，有无停帧、闪烁或触摸失效。
3. 保存 USB 与 host 日志，按既有流程导出持久日志为 `logs/sweetlog-0121a38-abi608-panel-pipeline.bin`。异常记录操作顺序；复测使用新后缀保留本次记录。

日志重点是新命令引用与既有完整完成顺序：

```text
SWEET MDSS DSI CLOCK: per-transfer leases enabled; shared BOOT/core retained
SWEET MDSS DSI CLOCK: acquired token=... mask=...; running branches shared
SWEET MDSS DSI CLOCK: released token=... after command idle; shared owners retained
... step=command-clock-held ...
... step=command-clock-released ...
OFF：HS停止 → ULPS进入 → ESC0 halted → PHY关/资源停放 → OFF complete
ON ：ESC0 running before host → host/PHY与ULPS → ON表17包LP/4DMA
     → display引用 → 六包HS色彩/1DMA完成 → 首帧 → HS亮度完成
     → 同generation第二次kickoff/真实新帧 → 触摸恢复 → ON complete
```

取得/归还 INFO 仅成对打印前8次；普通 ON 的 `traceWake` 另有 held/released，OFF 不打印该 ON 专用跟踪。日志停止输出不代表引用停止管理，发出请求也不算完成。

BUG-006 日志问题、BUG-008 首次亮度及 BUG-009 音量问题保留；BUG-007 旧画面闪现按用户要求暂缓，只记录是否复现。a38 通过后再推进 C08 外层 DSI/MDP 引用及其余 PD4，之后 PD1/PD5→F5→F7；不以本次打包代表完整资源管理或节电验收。

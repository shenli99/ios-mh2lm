# C7：VIDEOCC、CAMCC、GPUCC 的最小接入

[返回总计划](../CLOCK-SYSTEM-IMPLEMENTATION-PLAN.md)。各卡默认遵守[总计划 3.5 共享约束](../CLOCK-SYSTEM-IMPLEMENTATION-PLAN.md#35-所有卡共享的默认约束)，卡内只写特有边界。状态：未开始。

## 阶段目标与退出条件

三个控制器各自从初始化、只读查询、一个 gate 开始；没有实际外设驱动时，只登记控制器局部证据，不声称视频、相机或 GPU 工作。每个控制器首次写之前补齐 C0-03 格式的安全样本卡。频率、PLL、GDSC、reset 等后续能力分别实例化 C9 扩展卡；不要求本阶段一次实现全部资源。

各控制器仅在 C0-04 清单中有对应消费者时实施，否则整组标“暂缓（无需求）”。NPUCC、SCC 不在本阶段，其范围结论见 C0-05；若判定需要，按 C7 同样的 初始化→查询→gate 三卡模式另立 C7-N／C7-S 卡。

### C7-V01 初始化 VIDEOCC

- **目标**：IOQcomVideoCC 匹配并取得基础资源。
- **前置**：C1-02、VIDEOCC 的所有权和访问条件调查完成。
- **需求与边界**：只映射已声明窗口，识别 SoC 变体并注册未支持能力；不写 PLL／GDSC／reset，不预先分配 DMA 缓冲。
- **本地检验**：缺窗口、错误变体、访问依赖未满足及退出清理。
- **实机检验**：初始化事件及可合法读取的身份／配置样本；无可访问身份寄存器时只验资源初始化，读功能保持未证。
- **预期结果**：VIDEOCC 服务建立，写计数零。
- **失败归属**：C7-V01 map／variant／access／publish。

### C7-V02 查询一个 VIDEOCC 时钟

- **目标**：读取一个已知 video clock 的配置和继承状态。
- **前置**：C7-V01；查询类型已实现，相关域可访问。
- **需求与边界**：只一种解码类型；无可信父源则 Unknown，不因无 video consumer 就假定可关钟。
- **本地检验**：参考字段、未知父源与不可读状态；无写操作。
- **实机检验**：样本 ID、原始字段和解码结果对应；无法读取时返回明确依赖原因。
- **预期结果**：该资源只读查询成立，不宣称视频解码器可运行。
- **失败归属**：C7-V02 read／decode。

### C7-V03 控制一个 VIDEOCC gate

- **目标**：用统一接口完成一个获准 video gate 的本方 enable／disable 周期。
- **前置**：C7-V02、公共门控已验、样本可停止／独占且父源与电源满足。
- **需求与边界**：只一个已支持类型 gate；不改 root／PLL，不启动视频 DMA。若需新 gate 类型，先实例化 C9 的算法卡，本卡只接入既有算法。
- **本地检验**：描述与公共操作对应、访问 fence 和邻位保留。
- **实机检验**：该 gate 的请求／写／类型特定完成／撤回完整；无安全样本则受阻。
- **预期结果**：VIDEOCC 的一个 gate 可用，视频功能仍未验。
- **失败归属**：C7-V03 binding／gate-phase。

### C7-C01 初始化 CAMCC

- **目标**：IOQcomCamCC 匹配并取得基础资源。
- **前置**：C1-02、CAMCC 所有权和访问调查完成。
- **需求与边界**：只映射／注册；不遍历读关闭 island，不写 sensor MCLK、PLL、GDSC 或 reset。
- **本地检验**：缺资源、错误变体、域不可访问和初始化失败清理。
- **实机检验**：服务初始化成功且写计数零；允许地址以外不发起访问。
- **预期结果**：CAMCC 服务建立，不触发相机供电或外部引脚变化。
- **失败归属**：C7-C01 map／variant／access／publish。

### C7-C02 查询一个 CAMCC 时钟

- **目标**：只读取得一个已核实 camera clock 的选择与配置。
- **前置**：C7-C01、该资源访问条件成立。
- **需求与边界**：只一个 clock／一种已有类型；外部 MCLK 输出、电气测量和 sensor 初始化不在本卡。
- **本地检验**：parent-map、字段及未知状态，禁止读不可访问域。
- **实机检验**：样本原始值和解码结果可复查，未独立测量时不声称引脚输出频率已验。
- **预期结果**：该 camera clock 配置查询成立。
- **失败归属**：C7-C02 access／decode。

### C7-C03 控制一个 CAMCC 内部 gate

- **目标**：通过统一接口完成一个获准内部 gate 的本方票周期。
- **前置**：C7-C02、已验公共操作、安全样本及真实依赖成立。
- **需求与边界**：只一个内部 gate，不变更 sensor MCLK／pinctrl／外部供电，不启动相机数据通路。新 gate 算法先另卡完成。
- **本地检验**：时钟描述与寄存器掩码对应、类型特定状态及故障保留。
- **实机检验**：样本 enable／disable 及完成全链命中，外部相关配置未改变；缺样本则受阻。
- **预期结果**：CAMCC 一个内部 gate 可用，相机拍摄仍未支持。
- **失败归属**：C7-C03 binding／gate-phase。

### C7-G01 初始化 GPUCC

- **目标**：IOQcomGpuCC 匹配并取得基础资源。
- **前置**：C1-02、GPUCC 的 CX／GX 访问与所有权调查完成。
- **需求与边界**：只映射／注册，分别描述 CX／GX；不在 start 自动打开 GX，不动共享 GPLL 或 GPU reset。
- **本地检验**：域外／域内窗口访问门槛、错误变体、失败清理。
- **实机检验**：后端建立、写计数零；不访问未供电 GX，原 CPU 软件渲染保持。
- **预期结果**：GPUCC 服务存在，GPU 功能尚未开启。
- **失败归属**：C7-G01 map／domain-access／publish。

### C7-G02 查询一个 GPUCC 时钟

- **目标**：读取一个可访问的 GPUCC clock 配置及所需电源域。
- **前置**：C7-G01、查询类型已实现。
- **需求与边界**：只一个 clock，明确 CX／GX 与共享父源；不可读状态返回 Unknown／NotReady，不为查询启动域。
- **本地检验**：parent-map、访问条件和字段边界。
- **实机检验**：样本配置／依赖与调查一致，确认没有查询隐式上电。
- **预期结果**：该 clock 的只读状态可用，未证明 GPU 执行能力。
- **失败归属**：C7-G02 access／decode。

### C7-G03 控制一个 GPUCC gate

- **目标**：完成一个允许独立接管的 GPUCC gate 周期。
- **前置**：C7-G02、已验公共操作；样本域供电／corner 与停止条件均真实成立。
- **需求与边界**：只一个 gate，不能为找样本强开 GX，不重配共享 PLL，不发 GPU 命令。
- **本地检验**：权限、域依赖、描述与掩码及故障保留。
- **实机检验**：该 gate 的本方票写入及规定完成／撤回可查；GPU 电源依赖不具备时保留受阻。
- **预期结果**：GPUCC 一个 gate 可用，GPU 加速驱动仍为独立工作。
- **失败归属**：C7-G03 admission／gate-phase。

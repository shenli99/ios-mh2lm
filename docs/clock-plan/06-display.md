# C6：DISPCC 与现有显示资源逐项迁移

[返回总计划](../CLOCK-SYSTEM-IMPLEMENTATION-PLAN.md)。状态：未开始。

## 阶段目标与退出条件

把当前已经运行的显示资源分批迁入公共接口。**本阶段只迁移所有权和调用边界，不新增冷初始化、最后使用者物理转换或重建算法。** C08／PD4 剩余能力仍按原计划验收。

每次转交一个寄存器资源集之前，必须列明旧／新方、在途条件、保留票和不可逆边界；可采用“下一次启动只启用新 owner”的切换，不能在线强抢。共享 CC 窗口可以只读重叠，实际写操作必须逐资源唯一。

C6-07／08／09 分别记录“绑定／只读通过”和“写交接实机通过”。自然路径未执行写操作时，该卡的写交接目标仍为未验，不能把整卡标为实机完成；后续若会执行该操作，必须先补齐写交接证据，否则保持该操作禁用。不得让仅查询命中新 owner 的证据升级为控制能力通过。

### C6-01 初始化只读 DISPCC 后端

- **目标**：建立 IOQcomDispCC 并取得基础 MMIO／设备资源。
- **前置**：C0-02、C1-02；域外配置访问条件已核实。
- **需求与边界**：只登记资源与能力，不从 MDSS 接管写入，不启动／重配 PLL，不读取尚不可访问的域内寄存器。
- **本地检验**：错误映射／变体、访问依赖缺失和 stop 清理；初始化写计数为零。
- **实机检验**：后端 Ready、窗口与实际资源一致，旧显示首次接管仍成功。
- **预期结果**：DISPCC 服务存在；旧 owner 继续写，能力不虚报。
- **失败归属**：C6-01 map／access／register。

### C6-02 查询一个正在使用的显示时钟配置

- **目标**：让 DISPCC 的只读解码与现有 MDSS 对一个 clock 的认识一致。
- **前置**：C6-01、C1-03；样本访问条件成立。
- **需求与边界**：只读 parent／rate／gate 类型及继承状态；选择一种已有解码类型。新增类型先单独实例化 C9 扩展卡。
- **本地检验**：原始字段与现有解码逐项比对，未知状态不能猜默认值。
- **实机检验**：新旧查询来自同一模式／时间窗口，记录必要原始字段；不要求跨多次读取构造伪原子快照。
- **预期结果**：一个显示时钟的查询可信，尚未转交写权限。
- **失败归属**：C6-02 decode／snapshot-context。

### C6-03 转交一个显示 branch 的寄存器所有权

- **目标**：一个已用 branch 仅由 DISPCC 后端执行原有操作。
- **前置**：C6-02、C0-02；该 branch 算法在 C2／C9 已验或复用原 MDSS 算法。
- **需求与边界**：固定一个 branch 及旧租约账本；只搬迁执行位置，保留 enable／voted／settle 规则。MDSS 暂通过兼容调用使用它；不同时改 DSI／MDP 生命周期。每个额外 branch 另建 C6-03a／b 等独立卡及实机记录。
- **本地检验**：旧写路径消失，新旧操作轨迹相同；未排空、保留资源和部分失败处理一致。
- **实机检验**：该 branch 的一次原有自然请求命中新 owner，旧 writer 计数不再增长，画面及相关生命周期保持。
- **预期结果**：一个 branch 的单写者迁移通过；其余 branch 仍按所有权表管理。
- **失败归属**：C6-03/<branch-ID> handoff／write／completion。

### C6-04 将 DSI0 租约调用绑定到公共 clock 句柄

- **目标**：DSI0 原有租约仅经统一入口取得其已迁移的时钟。
- **前置**：DSI0 所需 branch 全部分别完成 C6-03 实例；公共句柄／引用能力已验。
- **需求与边界**：只替换 DSI0 调用和 token 映射；租约覆盖、命令／暂停／HS／ESC 时序与原实现相同，不放宽 PHY PLL 或电源权限。
- **本地检验**：真实显示调用链及取消／暂停回归；API 切换前后命令／clock 转换轨迹一致。
- **实机检验**：DSI0 token 明确来自新入口，亮度命令及原有 OFF/ON 中 DSI 获取／归还命中；记录最后显示 lifecycle 结果。
- **预期结果**：一个实际消费者完成公共接口迁移，不宣称其他租约已迁。
- **失败归属**：C6-04 bind／lease／DSI-use；底层 branch 失败记录具体 ID。

### C6-05 将 MDP 租约调用绑定到公共 clock 句柄

- **目标**：扫描使用的 MDP 租约经统一入口持有已迁移资源。
- **前置**：MDP 所需 branch 已逐项完成 C6-03；C6-04 普通路径稳定。
- **需求与边界**：只改 MDP 调用，保留 autorefresh／扫描／提交的原有引用范围；不改变 DMA buffer、帧提交或引用归零后的物理转换策略。
- **本地检验**：扫描持有、命令完成后仍扫描、停止排空等原合同；迁移前后转换轨迹一致。
- **实机检验**：新 MDP token 在真实扫描期间持续有效，停止／恢复事件与公共入口对应，最终新帧／FB complete 仍完成。
- **预期结果**：扫描消费者的接口迁移通过，C08 第5／6项剩余范围保持。
- **失败归属**：C6-05 bind／scanout-hold／release。

### C6-06 将显示 RSC 访问时钟租约绑定到公共入口

- **目标**：现有 display RSC 操作先通过公共入口取得其访问时钟。
- **前置**：对应 RSC branch 已逐项完成 C6-03；C6-05；域外访问及 corner／CN0 前置已保持。
- **需求与边界**：仅替换该租约调用；display RSC 本体仍由 MDSS 拥有，不在此移动 TCS／IRQ。取得租约前不得访问受门控的 RSC 窗口。
- **本地检验**：无租约／过期租约／父源丢失时无 RSC 访问；原流程无新依赖环。
- **实机检验**：lease Held 在 display TCS 读写之前，释放在原有完成之后；原数据带宽请求仍完成。
- **预期结果**：display RSC 有可供未来 channel 使用的单向依赖接口。
- **失败归属**：C6-06 dependency／lease／access-fence。

### C6-07 转交显示 GDSC 的既有底层操作

- **目标**：显示本地 GDSC 的已有操作改由所属 CC 的电源域接口执行。
- **前置**：C5-01、C6-01；现有 GDSC 写路径和 warm-only 边界明确。
- **需求与边界**：只转交该 GDSC，不搬 PLL／RCG，不新增冷态／真正掉电路径；迁移原有保护与状态，不强制运行未验的 C5-02／03。
- **本地检验**：旧直接写消失；域访问前置和原 MMIO 轨迹一致，未知状态拒绝。
- **实机检验**：原有 warm 生命周期命中新 owner；若自然路径未执行 GDSC 写，仅验绑定，写迁移项保留未覆盖，不能人为掉电补证。
- **预期结果**：既有范围内的域操作归属清楚；无实际写证据时只记绑定／只读通过，写交接仍未验。主动上／下电能力另按 C5 证据登记。
- **失败归属**：C6-07 handoff／domain-operation。

### C6-08 转交一颗显示 PLL 的既有操作

- **目标**：一颗已用显示 core PLL 的已有控制归属 DISPCC。
- **前置**：C6-01、该 PLL 所有权及依赖已明确。
- **需求与边界**：一次只迁一颗 PLL，复用原算法和参数；不涉及 DSI PHY PLL。第二颗另建 C6-08b，不同时新增频点。
- **本地检验**：旧写路径移除；warm 保留、cold 准入及错误轨迹与原实现一致。
- **实机检验**：该 PLL 原有自然查询／操作命中新 owner，不能仅因另一颗 PLL 锁定而通过；无主动操作则分别标“只读已验／写未验”。
- **预期结果**：有实际操作证据时登记该 PLL 的写交接通过；只有查询时保留写未验，不能判整卡实机完成。live retune 仍未授权。
- **失败归属**：C6-08/<PLL-ID> handoff／PLL-phase。

### C6-09 转交一个显示 RCG 的既有操作

- **目标**：一个原有显示 core root 的配置操作归属 DISPCC。
- **前置**：对应 parent PLL／固定源已稳定；C6-01。
- **需求与边界**：一次一个 root；保持原 parent-map、rate 和 update 流程，不增加 M/N/D 或新的 parent。额外 root 另建实例卡。
- **本地检验**：原始操作轨迹一致、旧写移除、错误 parent 拒绝。
- **实机检验**：该 root 配置／update 的自然路径命中并完成，实际 CFG 可解码；无触发时保留写未验。
- **预期结果**：该 root 的实际写入与 update 证据成立才登记写交接通过；只有查询时仍保留写未验。
- **失败归属**：C6-09/<root-ID> handoff／program／update。

### C6-10 将现有 core 资源协调改用公共句柄

- **目标**：原 MDSS core 流程只通过已迁移的 clock／domain 接口操作资源。
- **前置**：其实际会执行的 C6-07／08／09 写操作均已有对应实例的写交接实机通过证据；只用查询的路径可依只读证据推进，未验写操作必须保持禁用。原 corner 客户端可用。
- **需求与边界**：只替换 core 调用和异步完成衔接，原 core profile／时序／允许范围不变；不顺带实现 PD4 状态丢失恢复。
- **本地检验**：原 core 回归与部分失败／停止路径，跨 provider gate 不反向等待；无遗漏直写。
- **实机检验**：原 warm core 到 Ready 的事件链逐步对应公共 token，显示最终 complete；不能以 core Ready 代替最终消费者成功。
- **预期结果**：原 core 协调层保留，硬件操作经公共资源接口完成。
- **失败归属**：C6-10 orchestration／dependency-wait／core-ready。

### C6-11 建立 display RSC 的只读 channel 实例

- **目标**：公共 channel 可以识别 display DRV 的独立布局和依赖。
- **前置**：C3-01 的实例模型、C6-06、C0-02。
- **需求与边界**：只读 DRV／TCS 描述并保存 IRQ 资源；与 apps 不同的分组／DRV ID／IRQ 保持独立。MDSS 仍唯一写入；读取前需真实租约。
- **本地检验**：两通道身份不混、缺 lease 无 MMIO、布局错误拒绝。
- **实机检验**：取得 lease 后读到本通道配置，apps 与 display 记录可区分；旧 display 请求照常完成。
- **预期结果**：第二个实例可建立，尚未拥有其 IRQ／TCS。
- **失败归属**：C6-11 identity／lease／layout。

### C6-12 原样提取 display ACTIVE 执行器

- **目标**：把 MDSS 的 display TCS 执行机制变为内部公共模块调用。
- **前置**：C6-11、C3-03 的公共模块可承载该实例差异。
- **需求与边界**：保持 MDSS 为 owner，保持 display 现有 IRQ／顺序／期限／VCD 边界；不移动 BCM 聚合，不与 apps 合并队列／缓存。
- **本地检验**：提取前后 display MMIO／结果轨迹一致；租约、晚 IRQ 和故障保留回归。
- **实机检验**：一个原 display 请求经模块完成本通道 IRQ 和原后置条件；apps 票据继续独立。
- **预期结果**：执行代码可复用，所有权未变。
- **失败归属**：C6-12 extraction／display-sequence／completion。

### C6-13 将 display 执行器所有权转交 channel

- **目标**：display DRV 的 TCS／IRQ／在途状态由公共 channel 唯一持有。
- **前置**：C6-12、C6-06；转交期间 clock/domain 依赖不会反向等待 MDSS gate。
- **需求与边界**：只迁 owner，通过已建立的资源租约访问 RSC；MDSS 暂保留 BCM 语义兼容层。旧方写入被冻结，新 channel 不调用等待中的 MDSS 取资源。
- **本地检验**：转交失败、在途排空、IRQ 生命周期及访问租约丢失；旧写入口不可达。
- **实机检验**：本通道 ownership epoch、旧写冻结、新请求 trigger／INTID／cleanup 全链；同时验证 apps 通道仍能完成原请求。
- **预期结果**：两个 RSC 分实例，物理 writer 及依赖方向清楚。
- **失败归属**：C6-13 handoff／resource-hold／IRQ-owner／completion。

### C6-14 迁移一个不可拆分的 display BCM 投票组

- **目标**：一个现有有序 BCM／VCD 投票组的语义归属专用 voter 客户端。
- **前置**：C6-13、C3-08、C4-09；组成员与 commit／wait 边界已核实。
- **需求与边界**：一次只迁一个有原子／提交关系的组，不把 commit 依赖项拆开；其余组继续原兼容层，且每组只有一个聚合账本。后续组另建实例卡，不改算法。
- **本地检验**：原组成员、缩放、顺序、commit 和 ACK 轨迹一致；不同通道或 control 命令不被缓存吞掉。
- **实机检验**：该组自然请求记录全部成员及真实完成；数据票仍走 display RSC。其他组保持原状态。
- **预期结果**：一组数据带宽语义迁移通过，剩余组按实例继续。
- **失败归属**：C6-14/<group-ID> aggregation／encode／commit／completion。

# C8：状态集、PM 连接与局部恢复

[返回总计划](../CLOCK-SYSTEM-IMPLEMENTATION-PLAN.md)。各卡默认遵守[总计划 3.5 共享约束](../CLOCK-SYSTEM-IMPLEMENTATION-PLAN.md#35-所有卡共享的默认约束)，卡内只写特有边界。状态：未开始。

## 阶段目标与退出条件

先验证状态集的需求保存与硬件编程，再接入已经存在且可验证的系统 PM 入口。普通屏幕 OFF/ON、软件缓存失效和整机低功耗分开验收。本阶段依赖的 CPU suspend／电源入口若不存在，明确受阻，不在一张时钟卡内实现整套系统睡眠。

### C8-01 保存一个资源的 SLEEP 需求

- **目标**：一个 RPMh 客户端可独立表达并查询其 SLEEP 需求。
- **前置**：C4-04 的资源账本；类型的 SLEEP 语义已核实。
- **需求与边界**：只实现软件状态集聚合／dirty，不写硬件、不触发低功耗。原 ACTIVE 行为不改变；未支持资源明确拒绝。
- **本地检验**：ACTIVE／SLEEP 独立、别名需求、撤回、dirty 与 confirmed／desired 分离。
- **实机检验**：诊断请求后读到独立 SLEEP desired，ACTIVE trigger 数不因纯 SLEEP 修改增加。
- **预期结果**：软件 SLEEP 需求模型可用；不称 SLEEP 票已执行。
- **失败归属**：C8-01 context／aggregation／dirty。

### C8-02 保存一个资源的 WAKE 需求

- **目标**：为同一资源独立表达 WAKE 需求与已定义的 ACTIVE 关联规则。
- **前置**：C8-01；该资源的 wake／AO 规则有依据。
- **需求与边界**：只软件保存／聚合，明确 wake 与 active 是否联动以及谁负责；不默认照搬另一内核版本策略，不写 TCS。
- **本地检验**：ACTIVE、SLEEP、WAKE 三种 context 的组合、AO／普通别名及撤回；无意覆盖拒绝。
- **实机检验**：分别查询 desired 状态，修改 wake 不冒充 active ACK 或 sleep 执行。
- **预期结果**：状态集合同明确，不同需求不串线。
- **失败归属**：C8-02 wake-policy／context-state。

### C8-03 在获准的 SLEEP／WAKE TCS 中编程一组状态

- **目标**：将一个已聚合状态组 flush 到本通道拥有的 SLEEP／WAKE TCS。
- **前置**：C8-02；C0-02 已明确低功耗 TCS 的独占权和固件交接，solver／CPU PM 不会同时使用，布局和容量可核实。
- **需求与边界**：只一个通道、一个已知组，保留顺序／容量；按组更新状态，不触发 ACTIVE doorbell，不借用未拥有的 TCS。不能清空固件仍需的未知票。
- **本地检验**：dirty flush、容量不足拒绝、部分编程失败不标 flushed、与 ACTIVE 在途互斥；不得将部分状态交给 solver 使用。
- **实机检验**：在有明确空闲／禁止 solver 触发凭据的诊断条件下比对已拥有槽位；记录 flush 完成与版本。无法建立凭据则受阻，不试写。
- **预期结果**：状态组已正确装入硬件；未证明进入或退出低功耗。
- **失败归属**：C8-03 ownership／quiesce／program／flushed-version。

### C8-04 连接一个控制器的 IOKit Power Plane

- **目标**：一个已支持控制器的 PM 归属与资源描述一致。
- **前置**：C1-04；平台已有可用的 PM domain 注册位置和明确拓扑。
- **需求与边界**：只接一个服务的 PM 生命周期／状态声明；资源级多域依赖继续单独保存。能力未齐时拒绝非支持转换，不因添加 power parent 属性就假装完成 PM。
- **本地检验**：PMinit／注册／join／PMstop 配对、父服务晚出现／撤回；不在通知回调持锁等反向 provider。
- **实机检验**：Registry 的 PM 连接与预期一致，普通请求继续；未执行电源转换则仅记拓扑接入通过。
- **预期结果**：一个 PM 连接可复查，整机睡眠尚未验证。
- **失败归属**：C8-04 registration／topology／PM-lifetime。

### C8-05 在通道忙时拒绝一次低功耗准备

- **目标**：有在途请求或未成功 flush 时，PM prepare 返回明确拒绝。
- **前置**：C8-03；平台具备可调用、可退出的 PM prepare 入口，或已验的无掉电诊断入口。
- **需求与边界**：只实现准备阶段冻结新提交／检查在途与 flush 的准入；拒绝后恢复接受条件明确。本卡不进入 CPU 掉电。
- **本地检验**：准备与 enqueue／完成交错、在途／dirty／flush-failure 拒绝、取消准备恢复；无遗漏请求。
- **实机检验**：受控请求在途时调用 prepare，取得 veto 及后续原请求完成，确认没有进入掉电；没有可控入口则受阻。
- **预期结果**：低功耗准入不会丢失在途事务。
- **失败归属**：C8-05 freeze／busy-check／veto／unfreeze。

### C8-06 观察一个资源的真实 SLEEP／WAKE 执行

- **目标**：一次受控真实低功耗周期中，证明样本状态按 SLEEP／WAKE 计划执行。
- **前置**：C8-03／05；系统电源计划已提供可用的 enter／exit、唤醒及独立观测，不由本卡临时补齐。
- **需求与边界**：固定一个通道／一个资源／一种深度；观测指标在执行前指定，可为硬件状态、固件事件或独立测量。普通显示 OFF/ON 不作替代。
- **本地检验**：准备与恢复调用顺序、时间基准停止后的处理、缺观测时明确拒绝验收。
- **实机检验**：记录真实 enter、所需 SLEEP 结果、wake、所需 WAKE 结果及新 ACTIVE 请求完成；仅 TCS 寄存器读回不足以通过。
- **预期结果**：只该资源／该深度实机通过；无真实周期或观测则保持受阻／证据不足。
- **失败归属**：C8-06 enter-observation／sleep-effect／wake-effect／active-after-wake；系统未进入时归前置而非猜时钟故障。

### C8-07 重建一个本地资源的丢失配置

- **目标**：一个实际丢失状态的本地 clock／domain 能按受控需求重新建立。
- **前置**：相关 C5 能力已验；资源停机及真实状态丢失条件可证，恢复只依赖可访问的上游资源。
- **需求与边界**：一次一个资源或不可分割恢复单元，预先固定成员；按 desired 重建，不写回 ABL 快照，不同时恢复整条显示链。额外类型另卡。
- **本地检验**：缺失／部分恢复、parent 先于 child、旧 token 不复用，失败后未知状态不当成可用。
- **实机检验**：先取得真实丢失证据，再经配置／完成／消费者局部功能验证；仅软件清缓存不通过。
- **预期结果**：该恢复单元具备独立重建能力；显示端到端 PD4 仍需原计划验收。
- **失败归属**：C8-07/<unit-ID> loss-proof／parent-restore／local-restore。

### C8-08 重建一个 RSC 通道的传输状态

- **目标**：一个已发生可证实状态丢失的通道可重新执行合法 ACTIVE 请求。
- **前置**：C4-06；逐通道建立恢复引导依赖表，证明访问 clock／domain／供电被保留，或可经不依赖本失效通道的路径恢复；实际丢失的本地访问资源才要求对应 C8-07。物理 TCS 重置／丢失及旧在途不再执行的证明具备。
- **需求与边界**：只一个通道的 TCS／IRQ／epoch 重建；旧不确定事务不能未经物理终止证据就回收。desired 需求保留，未重投前不标 applied；首笔选择一个已验资源。若访问供电只能由本通道恢复，则本卡受阻，等待独立电源路径或明确的保留合同；不得引用依赖本卡的 C8-09 形成恢复环。
- **本地检验**：旧 IRQ／token 不完成新请求，confirmed 失效；重建失败保留隔离状态。
- **实机检验**：真实丢失／终止证据→访问资源恢复→新 epoch→新 ACTIVE trigger／IRQ／完成；未发生真实丢失则只记软件测试。
- **预期结果**：该通道恢复合同成立；不推导全部 VRM／ARC／BCM 已重放。
- **失败归属**：C8-08 loss-proof／transport-init／epoch／fresh-completion。

### C8-09 重放一个资源客户端的有效需求

- **目标**：在通道恢复后重新建立一个客户端仍有效的资源票。
- **前置**：C8-08；该资源的父依赖／重放顺序已核实。
- **需求与边界**：一次一个资源或不可分割依赖组；由语义客户端生成票，不由 RSC 遍历旧 raw 命令盲放。失效／退出消费者不得重放。
- **本地检验**：有效／已撤回需求、父先子后、部分失败、重复恢复；confirmed 仅随真实完成推进。
- **实机检验**：恢复前有效需求仍在，恢复后新命令和所需完成命中，消费者局部功能正常；其他未重放资源单列。
- **预期结果**：一个资源需求可恢复；全部系统恢复另按覆盖清单推进。
- **失败归属**：C8-09/<resource-ID> desired-selection／ordering／replay-completion。

## 日志判断

- 保留从资源获取开始到首错及后续状态的完整记录，重点是 CLOCK TIMEOUT / WRITE / SAMPLE 三条。
- `reason=branch-wait` 且 `current=1`：用本次样本的 `enable/off` 判断自身票未读回或时钟仍停止。
- `reason=overall` 且 `current=0`：本次 callback 尚未读 CBCR，样本为历史值或无效；结合时间和 valid 判断，不能当作超时瞬间硬件状态。
- `WRITE before/want` 是实际写入输入及目标，不是写后读回。`owned=0x80` 同样不证明使能成功。
- 若出现 CLOCK Held（state 2，mask 0x381），再追 NoC wrapper/solver/TCS 及首个后续错误或新 DMA。
  不以发出 enable 的 INFO 行作为接管成功证明。

## 实测：使能位未读回

2026-11-13。USB 日志 `logs/live-0121a24-abi608-panel-retained.txt`，222873 字节/3099 行，
SHA256=`df160b8bed570227a7c3b8dfc3356362c86439a549fd764ffea594fbaf954abb`。所需三条0211记录完整，无需补持久日志。

| 行号 | 观察 |
|---|---|
| 1727–1744 | 10 次 fresh ACTIVE IRQ；四 LDO、ARC、CN0 确认 |
| 1745–1747 | core2成功，AHB75/MDP460；CN0 token7确认；branch7发出enable |
| 1748 | 第一条 ERROR：reason=branch-wait，branch7，+0x4004；wait-late=103906ns，request-late=0 |
| 1749 | WRITE valid1，before0→want1，entry90549210104ns、issued90549233281ns |
| 1750 | SAMPLE valid1/current1，CBCR0、enable0/OFF0；parent-valid1、CFG0x40f/source4 |
| 1751–1757 | clock失败→NoC clock-status失败→managed失败；仍在phase2、display TCS未执行、未提交新DMA |
| 1759–1761 | 生命周期失败，pixels冻结；后续仍有用户态活动，无kernel panic签名 |

从写后记时到当前CBCR采样为10.081510ms；整体期限还剩187.727396ms。
采样比决策时间晚781ns，所以age=0符合0211的饱和显示规则，不是旧样本伪装当前。
这次已明确失败条件为自身enable未读回，不能解释成等待CLK_OFF清除或整体200ms/长延迟导致的超时。
也不能仅凭OFF0认定物理时钟可用或给予Held：还缺有效访问/自身票及完整资源链证据。

0211尚无紧随写入的读回和等待历史，因此无法区分从未置位与置位后丢失。
源码、实际内核store/屏障、LG/Lineage寄存器定义及本机ClockDxe地址表已进一步核对，未发现偏移或屏障错误。

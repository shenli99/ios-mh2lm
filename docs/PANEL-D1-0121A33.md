## 用户执行

先在接收终端运行：

```sh
sudo SWEET_ACM_DEVICE=/dev/ttyACM0 /home/shenli/work1/ref/ios-mh2lm/tools/sweet-usbacm-log.sh /home/shenli/work1/logs/live-0121a33-abi608-panel-pipeline.txt > /dev/null 2> /home/shenli/work1/logs/live-0121a33-abi608-panel-pipeline-host.txt
```

终端保持安静是预期行为；USB数据写入文件，连接/断开信息单独写入host日志。另一个终端执行：

```sh
fastboot boot /home/shenli/work1/out-bs/boot-16k-0121a33-abi608-panel-pipeline.img
```

1. 先确认能进桌面且画面持续更新。日志应有`command buffer ready bytes=4096`、`normal command enable generation=1; no CTL reset`、`configured generation=1`、fresh PP_DONE和`SWEET FB HANDOFF: active`。启动分配仍可能等待，不能把提前分配当成已修复的证明。
2. 首次接管正常后，息屏约5秒，再按电源键唤醒一次。检查画面、触摸、按键和亮度；从尝试唤醒起保持接收至少60秒，记录操作时刻。首次启动异常则保存该阶段日志，不继续OFF测试。
3. 保存上述USB和host日志，按既有流程导出持久日志为`logs/sweetlog-0121a33-abi608-panel-pipeline.bin`；需要再次采集时另加新后缀，不覆盖证据。

唤醒日志验收顺序：display引擎引用0、OFF complete；供电ACK/ULPS exit/host与panel reset；ON逐包真实完成、display引用1；generation2、TE-before-flush、新帧及触摸完成、ON complete、FB owned resume。启动之后不应再次出现命令缓冲allocate/prepare入口。缺失后续时按最后完成阶段定位，不将USB和持久日志视为独立线程栈证据。

## 验收和失败分流

先确认 CLOCK Held/state2/mask381，再按 RSC/NoC 的实际执行顺序检查：
进入 CLK、v2 初始化完成、TCS ownership ready、INTID161 configured、每组 fresh ACTIVE completion。
随后检查 NoC ACK、新 DMA 的 `submitted A=`、`transfer observed` 及 `SWEET FB HANDOFF: active`。
时钟 Held 和 NoC ACK 单独都不足以证明新帧接管成功。

若失败，保留完整上下文，按首个 RSC/IRQ/NoC/Link/Host/SCANOUT 错误继续定位。
没有 IRQ 时 POLL 的 samples0/status-valid0 表示未采样，不表示硬件状态为零。
不预先认定 a27 是丢中断；0216 仍需本轮硬件验证。

## 实测：初始化 index4 读回不相等

用户报告画面仍卡住。USB 文件 `logs/live-0121a28-abi608-panel-retained.txt`，
208507 字节 / 2957 行，SHA256：
`30b45bb8a9b0844e439f4391da637002bebd6a3766a86395ebc94253260864f4`。

| 原日志行 | 观察 |
|---:|---|
| 1761–1778 | apps INTID37 的 10 次 fresh ACTIVE 完成，LDO/ARC/CN0 已 ACK |
| 1781 | CLOCK state2/mask381，RSC 时钟租约 Held |
| 1782 | RSC enter CLK，wrapper override120、solver override0、modes1、status0/1/2均0 |
| 1783 | init readback index4/wrapper1/offset2020，wantffffffff，got224cac6 |
| 1784 | reason=rsc-takeover，group-valid0/group-count0/trigger-issued0；尚未提交 display TCS |
| 1785 | NoC IOError `0xe00002ca`，ACK0/uncertain1，保留票和时钟 |
| 1788、1791 | 未提交新 DMA，HANDOFF 连锁失败，pixels frozen |

本次首错早于 a27 的 ACTIVE2 等待，发生在 0216 新增初始化路径。
没有 v2 init 完成、INTID161 configured 或 display fresh ACTIVE 日志；不能据此判断中断本身失败。
1784 行有输出拼接/截断，但首错、未触发状态及后续失败记录齐全；无需仅为这次定位重采日志。
用户态和电池/USB 后续日志继续；屏幕卡住与显示接管失败一致，不等同整个内核停止。

Lineage 对这些 qtimer 写入不做全值相等检查，0216 增加的检查在实机触发失败。
0217 保留数值/顺序，将六项 CNTP 比较值/控制读回仅作诊断，其他检查和真实 IRQ ACK 条件保持。
这不证明硬件读值不同的物理原因，也不证明 NoC 或后续显示接管已经修好。
分析底稿 `scratch/framebuffer-0217/a28-log-analysis.json`；下一轮使用新内核，a28 无需重测。

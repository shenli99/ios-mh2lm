## 0219：补齐唤醒准入和命令进度打印

补丁 [0219-mh2lm-panel-wake-admission-evidence.patch](../xnu/patches/0219-mh2lm-panel-wake-admission-evidence.patch)
只增加诊断。未查明根因，不能称为黑屏修复。

新增 `SWEET PANEL WAKE:`，带 lifecycle token/phase、step/value、当前 lifecycle command token、
DSI token 和 completed/total；所有打印在已有 MDSS gate 内，仅取软件字段，不为日志增加外设 MMIO。
ON 前仍可能显示上一轮 OFF 的 DSI token/4of4，必须按 token 区分，不能当作 ON 完成。

- 在短暂的 pin activate/reset 阶段逐次记录 participants、local resources、provider leases、
  IRQ/DSI dependency 和 pin status 查询的进出。只记录首次轮询会漏掉复位完成后的那一次调用，因此每次都留阶段。
- `reset-proof-ready → command-enter → dsi-admission-enter → dsi-managed-* → dsi-registers-enter →
  dsi-sequence-ready → dma-route-* → dsi-timer-* → dma-allocate-* → dma-prepare-* → dma-physical-* →
  dsi-arm-enter → 原 D1 admitted → command-return` 区分准入阶段。
- PV ON 含超过 64-byte FIFO 容量的包，会首次检查 SMMU 并准备 DMA 缓冲区；a29 的 OFF 四条均走 FIFO。
  这是新经过的路径，**尚无证据证明 DMA 分配或 SMMU 是根因**。
- 每包打印 encode/registers/trigger-enter/trigger-return，以及真实 DMA_DONE+idle 之后的 packet-done。
  entry 只表示即将调用，return 只表示软件调用返回；真实完成仍由原判据决定。
- 每次新 lifecycle 重置预算，每次 ON 最多1024条阶段日志及一条上限提示；FAULT/STOP/完成后不继续打印。
  原生命周期超时出口补 token/operation/phase/command/completed 数值，便于区分卡住和正常超时处理。

真实 IRQ、DMA_DONE/idle、复位输入、fresh pixel、touch fence、资源权限、SMMU 和 buffer pin 判据不变；
不新增重试、复位、供电操作、启动参数或延长期限。0218 的 Lineage 配置观察策略保持。
增加日志可能影响短阶段调度时序；本地模拟不证明实机时序，下一轮须同时检查是否真的超时及发生阶段。

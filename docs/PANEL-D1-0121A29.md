## 用户实机操作

先在一个终端开启 USB 日志接收；脚本会等待设备出现并跨断连继续接收：

```sh
sudo SWEET_ACM_DEVICE=/dev/ttyACM0 /home/shenli/work1/ref/ios-mh2lm/tools/sweet-usbacm-log.sh /home/shenli/work1/logs/live-0121a29-abi608-panel-retained.txt
```

手机进入 fastboot 后，在另一个终端临时启动：

```sh
fastboot boot /home/shenli/work1/out-bs/boot-16k-0121a29-abi608-panel-retained.img
```

启动约 90 秒后 Ctrl+C 停止接收，保留完整 USB 日志，并记录画面有无更新、冻结或重启。
完整接管前亮度、OFF/ON、长测和 combined/supply 实机验证继续暂停，不重测 identity 或 a28。

## 日志检查顺序

`CLOCK Held → enter CLK → 65 项 CONFIG 观察 → v2 initialized → TCS ownership ready →
INTID161 configured → 每组 fresh ACTIVE completion/NoC ACK → PHY/host → 新 DMA/transfer/HANDOFF`。

`mismatch=1` 是配置差异打印，不单独代表流程失败；保存 stage/offset/want/got/mask。
如果后面真实 busy、锁定或完成等待失败，按首错连同之前的配置打印定位。
仍须真实本槽 IRQ/ISSUED/必要 COMPLETE，以及 fresh PP_DONE、flush 消退和帧推进。
没有 IRQ 时 POLL samples0/status-valid0 表示未采样，不表示寄存器实际为零。

boot-abi608-verification.json、packaging.txt 及两份 verify 脚本/输出。内核、镜像和原始日志不入 git。

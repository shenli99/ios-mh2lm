## 日志判断

保留从资源获取开始到首错及后续状态的完整记录。若仍超时，重点看六条：
CLOCK TIMEOUT / WRITE / SAMPLE / READBACK / OBSERVED / RSC PREFLIGHT。

- READBACK valid=1 且 enable=1，最终 SAMPLE enable=0：至少观察到一次使能，随后丢失；不能仅凭它指定清除者。
- 写后 enable=0，但 OBSERVED seen-enable=1：等待过程中曾观察到使能，结合首次/最后时间及最终值判断。
- 写后与等待均未观察到 enable：继续查访问映射、权限、局部域/复位及写入语义；
  不能证明采样间从未短暂置位，也不能直接归因 secure world。
- READBACK PA 预期为 `0x0af04004`。PA=0/异常是翻译问题线索；正确 PA 不证明总线接受写入。
- OBSERVED 只汇总原等待样本，不含紧随写入的一次读取；wait-samples=0 表示没有等待样本。
  valid=0 不能当硬件值，RSC PREFLIGHT 是历史准入样本。
- 保留 0211 的时间判读：overall/current=0 时不能把缓存 SAMPLE 当超时瞬间的硬件值。
  WRITE before/want 与 owned=0x80 都不是写后使能成功证据。
- 若 CLOCK Held（state 2，mask 0x381），再追 NoC 首错或新 DMA；不能仅凭发出 enable 的 INFO 行判定接管成功。

这次**没有观察到使能置位后再丢失**：立即读取及39次等待均未见enable。
OBSERVED只聚合enable/OFF两位，不能据此说39次完整CBCR值都为0；也不能排除采样之间极短暂置位。
READBACK PA匹配实际预期，排除了本次CPU翻译到其他物理地址的猜测；不证明总线接受写入或赋予权限。
另两路准入时已有enable，使“VSYNC根本没开所以branch7失败”的简单解释缺乏支持，但它们不是超时瞬间的新读值。
后续用户态活动继续，无kernel panic签名；画面静止与接管失败相符，不能归为内核死锁。

### 进一步静态审计及边界

- 实际a25内核 `advanceLocalClocks` 的内联路径包含：RMW bit0 → `dmb oshst` →
  `str w8,[x10,x26]` → `dsb sy`，随后同一base/offset的load，再调用ml_vtophys。
  没有发现编译器丢失store、读写使用不同偏移或缺少写后屏障。
- 本机mh2 ClockDxe的三路表项及通用callback已按PE RVA核对。
  NON_GDSC表项文件偏移0x30c90，HAL描述符从+0x18开始：
  CBCR=0x0af04004、reset=0x0af04000、alternate vote地址=0、callback表=0x431f0。
  RSCC_AHB/VSYNC的alternate vote地址也为0。
- 对应enable callback 0x11a9c在alternate vote地址为0时，对CBCR做bit0 RMW；
  is-enabled callback 0x11af8也读CBCR bit0。没有找到另一套应写的vote地址，
  也没有找到bit0应当只写或自清的静态依据。该核对不覆盖固件全部动态初始化。
- LG `dispcc-sm8150.c:1612`定义RSCC_BCR=+0x4000；
  ClockDxe reset callback 0x11b5c同样使用该表项的reset地址并操作bit0。
  **a25没有采集BCR值，因此不能声称复位仍被拉住，更不能据此直接写复位。**
- 必须区分完成判据：LG的enable路径是regmap RMW、屏障、branch2 halt等待，等待不额外要求enable=1；
  我们要求enable=1且OFF=0。CBCR0会满足LG的halt判据而被当前XNU自身票判据拒绝。
  因而“XNU拒绝接管”不等于“物理时钟已证实停止”。同时，参考驱动提供的is-enabled仍读取bit0；
  现有证据不足以将enable读零当作当前生命周期已获得稳定时钟所有权。

已据此实现[0213](PANEL-RSC-LOCAL-RESET-EVIDENCE.md)：warm core入口及branch7写入前各采集六项局部状态，
失败时仅补一次BCR读取，结合原当前/历史CBCR样本判断；保持现有完成判据/期限/失败保票和NoC/DMA准入。
用于区分继承状态、core转换期间的变化与局部复位线索；若BCR始终清除，仍需继续查写入语义/访问条件，
不能自动转而宣称secure world拦截。本地验证已通过，需云编译新产物；仍未交付已证明的硬件修正。

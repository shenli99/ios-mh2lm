## 日志判断

若仍在 branch7 超时，原六条记录之外应有以下三条。
LOCAL 在阶段入口采集、在超时日志中输出；依据 sampled-ns 区分采样时间，不能以输出位置代替采样时间。

| 新记录 | 内容与采样阶段 |
|---|---|
| CLOCK LOCAL: stage=warm-entry | warm core 原准入通过后、core 寄存器转换前：BCR、三路 CBCR、AHB CMD/CFG |
| CLOCK LOCAL: stage=pre-write | branch7 原写入检查通过后、enable 写入前：同样六项 |
| CLOCK RESET | 超时出口通过原前置检查后，仅新读 RSCC_BCR |

寄存器为 DISPCC+0x4000、0x4004、0x400c、0x4008、0x22bc、0x22c0。
LOCAL 是按顺序采样，并非原子快照；valid=0 时不能把零字段当硬件值。
RESET 只报告 BCR，不能把旧 CBCR 样本视为同时新读；overall/current=0 的 SAMPLE 仍是历史缓存。

- 比较 warm-entry 与 pre-write：是否在 core 转换阶段出现 BCR 或局部时钟变化。
- 比较 BCR bit0 在三个阶段的状态。置位支持复位请求线索，但不能单凭它证明 enable 读零的因果关系。
- 若三个 BCR 样本均为0，排除所采样时刻的简单复位位解释，继续评审写入语义及本地额外 enable 门槛。
- a25 的 OFF 已为0，满足 Lineage 开启 halt 检查；当前 XNU 拒绝来自额外 enable 条件。
  本版未修改该条件，不能将相同超时称为已证实的硬件 halt 握手失败。
- 若 CLOCK Held（state 2，mask 0x381），保留后续 NoC / 新 DMA / HANDOFF 记录；
  正常成功路径不会输出这些超时 ERROR，不能仅因缺少 LOCAL 就判取证失败。

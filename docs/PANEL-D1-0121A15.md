## 实测结果：ESC0 的合法 XO 旁路被错误拒绝

持久日志`logs/sweetlog-0121a15-abi608-panel-retained.bin`，SHA256
`42c6f5f060029d9e9577b13b589f31674d35da80c6226d3332445591c1a18ab1`，total=265904/flush=18，
383行605字节参数与打包配置完全一致。639行SpringBoard启动，未见panic。

| 解码行 | 本机读值 | 结论 |
|---|---|---|
| 85 | accepting=1/inactive=0/fault=0，link/host/core=0 | 首次软件准入正常 |
| 86 | GCC AHB=0x80000003、DISPCC AHB=1、HF=0x4221、GDSC=0xf822f000 | 总线与域检查通过 |
| 87–92 | AHB CFG=1、MDP CFG=0x100107、VSYNC CFG=1；各CMD=0 | 前三分支通过 |
| 93–95 | ESC0 CBCR=1、root=0x2148、CMD=0、CFG=0；gate=xo-config | 首个拒绝点是XO编码判断，随后start早退 |

LG参考`android_kernel_lge_sm8150` commit
`d4f335e13d73c4aa2af85581a6ec11b670ee5b94`：`drivers/clk/qcom/clk-rcg2.c:241–249`
只有HID非零才计算`parent × 2 / (HID + 1)`。所以HID=0是旁路，HID=1是div1，
在整数模式下均保持XO 19.2MHz。`dispcc-sm8150.c:755–770`确认ESC0 root为0x2148、
HID宽5且M/N宽0。旧`clockParent()`强制`(CFG & 0x371f) == 1`，漏掉合法的0，
这次不是硬件时钟掉电；也不是GDSC或固件ABI失败。

服务仍未发布，BYTE/PCLK以及managed资源链、完整面板OFF/ON未执行；不能扩大为所有时钟
和完整面板驱动已验证。按建议本轮未测试息屏，日志没有新增FB freeze，不能据此称已恢复。
另有3条旧USB command warning、15条HFS clonefile -34及3条BindFS ENOENT，独立记录，
本补丁不声称修复它们。解码和分析底稿保留在`scratch/artifact-0121a15/`。

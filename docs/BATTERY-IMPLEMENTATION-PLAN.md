## 目标、架构与范围

本阶段完成**可重复启动的基本有线电池管理**：真实测量、受约束的充电控制、
温度/故障保护、事件刷新及标准IOPM发布。退出对“恰好继承允许充电配置”的
依赖；保留已有按键/USB/触摸IRQ，完成电池CHGR正常事件验收。

继续使用以下责任边界，不重写已建立的发现机制：

| 层 | 责任 |
| --- | --- |
| 共享SPMI transport | 事务锁、APID/读写ownership、受限地址访问、返回码/超时；提供必要的原子掩码更新与有界事务 |
| SweetSpmiInterruptMux | 唯一共享GIC入口、路由配置/ack、attach/detach与事件投递；不承担充电策略 |
| 电池consumer自己的IOWorkLoop | 接收事件、采样、串行策略计算与控制提交，管理必要timer和退出 |
| 电池内部采样/充电控制组件 | 区分硬件访问、策略仲裁和IOPM发布；先作为现有服务内部组件，明确接口，避免另造全局单例 |
| SweetBattery / IOPMPowerSource | 发布真实状态及有效性，通过updateStatus通知powerd；保持现有iOS兼容服务 |

原mux电池route写接口继续只允许IRQ寄存器。充电控制使用transport层新接口，
所有SPMI访问共用现有控制器锁；不绕开锁，也不扩大mux写入口承担策略。
多寄存器控制在consumer loop上串行；单笔RMW在transport内保持原子性。
SRAM另有有界会话和grant/release，设计好锁顺序，不能跨等待无限占用共享锁。

资料以工作区 `docs/INDEX.md` 六章和LG目标源码为准。温度/电池profile/并联
拓扑按实际MH2LM核对，不直接照搬小米板参数。使用读取返回码和原始值区分
未知与零；日志按现有ERROR/WARN/INFO/DEBUG分级，记录决策原因。

## 六个任务段

| 段 | 交付物 | 结束条件 |
| --- | --- | --- |
| 1. 共享访问与控制接口 | 受限读写/RMW、组件边界、生命周期与故障接口 | 本地错误注入通过，共享访问不破坏按键/mux；观察档没有充电策略写入 |
| 2. 真实测量与配置核对 | 电流/温度/电压/SOC及来源、输入/充电参数快照、电池和并联拓扑依据 | 关键数据有效且有时效；可解释实际电源模式、FCC/FV及保护配置，缺失项显式阻止使能 |
| 3. 策略与保护 | 状态机、限流限压/禁充仲裁、超时与退出、模拟决策档 | 模拟场景和实机观察中决策一致，所有不满足条件的路径均不请求使能 |
| 4. 首次受控充电 | 约束内配置、最后使能、回读和持续测量 | 从已记录的禁充初态受控进入真实充电，并能受控停止；取得CHGR事件证据 |
| 5. 运行期事件管理 | 插拔/识别变化、温度限制与恢复、故障、息屏与重启处理 | 多次插拔及亮/息屏稳定，无静默回退或继承状态依赖，保护可验证 |
| 6. 完整上报与回归 | 容量/状态字段清理、多档回归与可复用硬件记录 | UI/IOPM与真实硬件一致，基本有线管理和电池IRQ正常路径验收 |

“一次编译”不等于必须同时启用所有阶段。源码实现可合并进同一个内核，参数
选择观察、准备/模拟、受控充电或组合回归；验收仍按依赖推进。具体参数名称
与数值在实现时写入打包工具和文档，不在此提前声称已有可用开关。

### 第1段：共享访问与控制接口

1. 整理observer与writer API，按SID/地址/宽度明确允许范围；Type-C确需读取时
   先核对目标APID、寄存器语义，再按目标开放，不盲扫或整片解除白名单。
2. 确认CHGR、DCDC、USBIN、MISC所需write_ee，不从IRQ接入成功推导所有写权。
   writer只开放设计中实际使用的地址；普通配置RMW与W1C/触发命令分开。
3. 统一错误/超时、回读、失效状态和日志。明确transport锁、mux gate、consumer
   loop及SRAM会话的锁顺序，保持按键/电池并行时共享控制器安全。
4. 明确初始化、取得控制权、停止事件、取消timer、撤销回调和资源释放顺序。
   观察模式不取得充电控制权；取得控制权后的失败/退出须走已设计的停止流程。

**验收：** 本地测试覆盖掩码保留、拒绝越权、超时、并发、初始化失败和退出；
观察档在实机上保持现有三键/USB/触摸/电池事件。阶段不靠试写enable验证。

### 第2段：真实测量与配置核对

1. 合并0149的逐字段有效性，保留原始码、换算、来源和采样时间；电流读取匹配
   IBATT影子，电压也核对直接值/影子一致性。保持已验证MSOC缩放与防跳变。
2. 取得真实电池温度。LG Gen4标准TEMP经SRAM，需按REVID完成有界request/
   grant/read/release和版本workaround；如选择直接RRADC路径，先验证单位、
   热敏模型与LG修正，不能把0x4288定义或25°C占位直接视为可用温度。
3. 核对输入及模式：APSD状态/结果、需要的Type-C sink状态、USB suspend、
   ICL值与0x1366/1342/1365模式、0x1108 settled ICL，区分设定与实际输入。
4. 记录FCC/FV、ITERM/recharge相关继承配置、热保护、watchdog、CHGR状态/
   故障、SMB_CFG和override。判定哪些参数保留、哪些必须显式配置。
5. 核对实际电池ID/型号、profile状态与允许的电压/电流上限。DTS的BLT42命名
   是参考，5020mAh占位不是本机已测值；不能据此直接选择充电上限。
6. 核对SMB1355是否参与当前电流路径。若首版采用主路，须先证明并联已安全
   隔离并可保持，不能仅因XNU没有I²C驱动就假定并联未运行。确需I²C支持时
   单列依赖、复用/补最小接口，不偷偷跳过总电流约束。

**验收：** 关键测量有效、符号/单位正确且时效可判断；能够依据电池与电源条件
制定受限策略。访问失败/过期明确报未知，不能用占位温度批准充电。SRAM读取
只为必要遥测/身份取证，不默认重载profile、写学习数据或调MSOC门限。

### 第3段：策略与保护，先运行模拟决策

1. 设计并实现未就绪、无输入、准备、允许充电、温度限制/暂停、满电和故障等
   状态，记录每次转换原因。将外接电源、允许充电、实际充电与满电分开。
2. 实现统一禁充原因集合，以及ICL/FCC/FV上限仲裁；初版可用简单原因表和
   最小值计算，不要求移植Linux votable框架。未知电源能力按明确的保守规则
   处理，不把“寄存器配置1500mA”当作电源已承诺1500mA。
3. 首版走常规有线输入；策略不主动请求QC/PD快充。检查/处理启动时已经存在
   的高压会话，不能因为本驱动没发起协商就假定VBUS一定为5V。
4. 温度保护包含有效性/时效、迟滞和恢复；数据失效、电池缺失、异常输入、
   配置失败、watchdog问题都进入明确的停止/故障路径。
5. 定义取得控制权时的快照与安全过渡：必要时先停充、约束主/并联路径，再
   配置和回读，所有条件满足才允许使能。回滚不能盲目恢复旧enable1或高限值。
6. 运行模拟决策档，只输出计划动作，不提交充电策略写入。模拟决策验证不
   等于保护硬件已验证，也不等于正在禁止固件已经开启的充电。

**验收：** 本地故障/状态转换测试与实机观察均能解释决策；未知/过期温度或
无有效输入不会请求使能。首次充电前，基础温度监测、会话期限、退出/故障
停止和watchdog处理必须已经存在，不能等到第5段才补基本保护。

### 第4段：首次受控开启，证明实际充电

仅在前3段证据通过后，使用同一内核的受控档，限定测试时长并持续监测保护
条件。优先在已确认的常规5V独立充电器/线下，以实测电源与电池约束设定限值。

1. 保存初始enable/阶段/电流与配置。若初始enable1，先按设计安全停止并回读，
   使这轮能验证本驱动的开启过程，而不只观察继承的充电。
2. 按目标初始化顺序约束输入、主路/并联、FCC/FV与保护，逐步检查返回码和
   回读；仅在最后开启0x1042 bit0。不套用全量Android probe作为初始化脚本。
3. 开启后检查实际阶段、电流方向和趋势；追踪CHGR自然命中及包含0x2的刷新，
   不以写成功或状态栏闪电作为真实充电证据。
4. 到期、主动停止或保护触发后禁充并回读。通信失效导致无法确认禁充时明确
   报错并中止验收，不能承诺总线故障下软件一定能成功关断。

**验收：** 同一次会话有“禁充初态→配置有效→使能→实际充电→受控停止”证据，
持续匹配负IBATT和SOC/电压趋势相互支持；标准IOPM电流需正确转换符号。
CHGR中断独立投递得到验证，三键/触摸/ACM仍工作。失败保留原始记录，按层
定位，不静默降级为轮询或重刷旧镜像掩盖。

### 第5段：运行期事件、热管理与恢复

1. 在已有USBIN/CHGR/MSOC/SOC_READY基础上，按需接入APSD/source-change、
   温度/电池缺失/故障事件；扩充路由表和consumer事件描述，所有新源先核对
   ownership、极性、ack与风暴退出，不另占共享GIC入口。
2. 插入后重估输入能力；拔出、输入类型变化、温区变化、满电/recharge和故障
   各自驱动状态机。异步识别只做有界确认/重试，失败显式保守处理。
3. 温度/遥测与watchdog按实际需求使用timer；温区事件和定时监测互补。不能
   仅在MSOC变化时检查温度，也不能以“全部IRQ化”为由删掉必要保护任务。
   timer频率、空闲停用和时效预算在实现时记录；不恢复两秒插拔轮询兜底。
4. 覆盖息屏后的监测/限流、拔插唤醒与输入恢复。当前display-off不等于深度
   休眠；未来真正睡眠前必须另行保证唤醒源、硬件保护及watchdog责任。
5. 完成停止/服务终止/重启交接，验证迟到事件不访问已释放对象，明确固件接手
   前的硬件状态。USB数据枚举与电池输入状态分别判断，保留现有日志通道。

**验收：** 多次插拔、不同初始状态、持续充电及亮/息屏稳定；模拟温区、过期
测量和配置失败时限制/停充及恢复正确，不通过实机过热制造故障。停止、恢复
和真实服务清理分别留证，不能由“正常使用没出错”替代。

### 第6段：完整上报、容量清理和组合验收

1. 向IOPMPowerSource发布已验证的真实电流/温度；未知值和过期样本有明确
   语义，不能继续把固定25°C或0mA展示成实测。保留updateStatus通知链。
2. 依据已核对的电池/profile及可读容量数据替换5020mAh占位，区分设计容量、
   满充容量与剩余容量；标明估计值，校正SOCEstimated等属性语义。
3. 未实现循环学习/健康度/剩余时间等明确未知，不伪造已完成。核对状态栏、
   锁屏充电提示和powerd读取；已有framebuffer重绘缺陷单独归档。
4. 运行组合矩阵：开机已插/未插、启动enable0/1、插拔/来源变化、亮/息屏、
   电量与充电阶段变化、输入驱动并行、标准/诊断档和必要异常退出。
5. 将原始日志SHA、内核/固件/参数、配置/写入/回读、操作及测量写入文档。
   历史m20文件身份不符不得混入验收。

**验收：** 基本有线充电可重复、不靠初态偶然成立；电池IRQ正常路径及必要
保护有证据，IOPM/UI与硬件吻合。SOC_READY若无自然转换，记录未覆盖，不强制
复位FG。复杂容量学习、profile重载、快速充电、无线/并联优化另立后续任务，
不以这些高级功能无限延后电池IRQ结案和既定framebuffer目标。

## 编译与测试组织

- 第一批尽量合并第1～3段的可独立实现部分：一次构建，分别生成观察、遥测/
  访问预检、策略模拟档。0149不必为取得新编号而单独消耗一轮编译。
- 第4段的控制代码可与前述实现同编译，但默认关闭；仅当前置条件已由日志
  确认后选择受控档。若依赖尚未实现则不打包这个档，不能靠参数跳过检查。
- 第5～6段尽量合并补强，生成单项及全事件回归档。实际构建批数由硬件结果
  决定，不承诺六段只需固定几轮，也不要求每段单独云编译。
- 每批先完成适当的本地编译/故障测试和patch应用校验，再由用户push；下载
  后核对实际源码/内核标记并制作boot。fastboot与设备操作继续由用户执行。
